# 네이버 여행 글 만들기

블로그 정체성은 **"어디가지?"** — 장소를 소개한다. 상위 글 실측 기준은
`references/learned.md`, 라쿠아 실전 기록은 `references/laqua-embeds.md` 에 있다.

**한 문장으로**: 사진을 먼저 모으고 눈으로 고른 뒤, **사진이 글의 구조를 정하게** 한다.
글을 먼저 쓰고 사진을 나중에 끼우면 사진과 문장이 서로 다른 곳을 가리킨다.

---

## 0. 목소리 — 먼저 정해야 할 것

우리는 **가 보지 않았다.** 상위 글의 힘인 "내돈내산" 은 우리가 할 수 없는 주장이다.
그래서 **사진으로 안내하는 소개자** 목소리로 쓴다.

| 쓴다 | 쓰지 않는다 |
|---|---|
| "이 컷을 보면", "여기까지 돌면 세 시간은 금방 가요" | "직접 가봤는데", "내돈내산" |
| "저라면 3~4시간을 비워 둘 것 같아요" | "물이 미끌미끌했어요" (몸으로 겪은 감각) |
| "공식 안내에는 …로 적혀 있어요" | 출처 없는 수치 |

- 어미는 **`~어요/예요/잖아요/더라고요`** 구어체. 뉴스체(`~했다/~이다`) 금지.
- 문단은 **한 호흡, 20~30자.** 발행 실측 median 19 / p75 22 가 목표치다.
- 사진 묘사는 **눈으로 확인한 것만.** 간판 문구·안내판 표기·건물 모양은 근거가 된다.

---

## 1. 사진을 모은다

사진이 없으면 글을 시작하지 않는다. **스톡 사진은 쓰지 않는다** — 실측에서 스톡은
"아무 사우나", "두바이 호텔" 을 물어왔다. 장소·아이템·히트 요소는 정의상 그 장소의
사진이어야 한다. 그래서 `images.stockPhotos: false`.

### ① 인스타 — 분위기·시설·아이템

```
node scripts/ig-photos.mjs --title "글 제목" "https://www.instagram.com/p/XXXX/" …
```

- `out/photos/ig/<제목 슬러그>/` 에 번호를 이어 담고 `manifest.json` 이 출처를 기억한다
- 같은 제목으로 다시 부르면 이미 받은 컷은 건너뛴다
- ⚠️ **원저작자 사진이다.** 수집은 후보를 눈으로 고르기 위한 것이고 발행 허가가 아니다.
  실제 게시는 ① 임베드/`oglink` ② 공식·라이선스 사진 ③ 작성자 허락 중 하나로 간다

### ② 위키미디어 공용 — 역 안내판·개찰구·출구·외관

인스타로는 **"가는 길" 컷이 안 모인다.** 공용은 철도 시설이 촘촘하고 CC 라이선스라
표기하면 실을 수 있다.

```
node scripts/wm-photos.mjs --search "Korakuen Station sign"          찾기
node scripts/wm-photos.mjs --title "글 제목" --file "이름.jpg" …      받기(같은 폴더)
```

- 받을 만한 것: **역명판**(한글 병기가 있으면 최상), **방면 개찰구**(안내판 문구가 보이는 컷),
  환승 개찰구, JR 출구, 지상 역사, 건물 외관
- ⚠️ **계절 이벤트 사진은 버린다** — 크리스마스 일루미네이션을 상시 정보처럼 쓰면 속이는 것
- ⚠️ 429 가 나면 도구가 알아서 기다렸다 다시 부른다 (축소본을 서버가 그때 렌더링한다)

### ③ (선택) 연출컷 — AI 인생샷

`node scripts/ai-influencer.mjs --title "…"` — 표지·연출 자리에만. **장소를 증명하지 않는다.**
간판·요금표·시설처럼 사실을 증명하는 자리에는 실사만 쓴다.

## 2. 눈으로 고른다 → `pick.json`

받은 사진을 **전부 본다.** 파일명만 보고는 고를 수 없다.
폴더에 `pick.json` 을 만들어 컷별로 무엇이 찍혔는지, 어느 섹션에 쓸지 적는다.

```json
{ "items": [
  { "n": 17, "what": "'東京ドーム天然温泉 Spa LaQua' 금색 실내 간판",
    "tags": ["장소확정"], "use": "s1", "why": "글의 핵심 사실을 사진이 증명한다" },
  { "n": 3, "what": "발 올린 시점", "use": "drop", "why": "정보가 없다" }
] }
```

고르는 기준 네 가지 — **정보가 되는 감성 사진**만:

| 기준 | 뜻 |
|---|---|
| 장소 | 어디인지 알아볼 수 있는 컷 (입구·간판·전경) |
| 아이템 | 가져갈 정보가 되는 물건 (어메니티·음료 컵·티켓·관내복) |
| 히트 요소 | "이거 보러 간다" 는 대표 장면 (노천탕·야경) |
| 감성 | 저장하고 싶어지는 톤 (조명·수증기) |

버리는 것: 얼굴·신체가 주인공인 컷, 장소를 알 수 없는 클로즈업, 계절 한정 이벤트.
**17장 중 1~2장은 버리는 게 정상이다.**

## 3. 아티클 JSON 을 조립한다

`out/<stamp>-<제목>.json`. codex 초안이 있으면 사실(요금·시간·규정)은 그대로 두고
**문단·사진 배치는 가진 사진에 맞춰 다시 쓴다.** 초안의 `photoQuery` 는 스톡용 지시라
실제 사진과 맞지 않는다.

```jsonc
{
  "photoDir": "out/photos/ig/<제목 슬러그>",   // 이것만 있으면 사진이 따라온다
  "bodyImageCount": 21,                        // imageBriefs 의 body 개수
  "intro": ["안녕하세요, …", "도쿄 여행은 하루 2~3만 보가 기본이잖아요…"],
  "directAnswer": "…",                          // 맨 위 한 줄 정리 (quotation_line)
  "sections": [{
    "heading": "고라쿠엔역 안내판부터 라쿠아 6층까지",
    "lead": "역에서 헤매지 않는 순서",          // 대목 머리말 (quotation_corner)
    "paragraphs": ["…20~30자씩…"],
    "bullets": ["역별 도보 시간처럼 스캔하는 정보"],
    "table": { "caption": "", "headers": [], "rows": [] },  // 요금 같은 것만
    "callout": "팁·주의 한 줄"                  // (quotation_postit)
  }],
  "imageBriefs": [{
    "placement": "body",
    "photo": "<슬러그>-18.jpg",   // 폴더의 파일 이름
    "afterSection": 1,            // 몇 번째 섹션에
    "afterParagraph": 3,          // 몇 번째 문단 뒤에 (1-based)
    "group": "g-arrive",          // 같은 값이면 두 장을 나란히 묶는다
    "caption": "역명판에 '고라쿠엔' 이 한글로도 적혀 있어요",
    "alt": "고라쿠엔역 남북선 역명판 — 한글 고라쿠엔 표기"
  }]
}
```

### 품질 목표 (검색 상위 8편 실측)

| 항목 | 목표 | 왜 |
|---|---|---|
| 인용구 | **8~15개** | 상위 글은 인용구를 소제목처럼 쓴다 (corner 또는 line 한 종류로 통일) |
| 캡션 | **사진 수의 70% 이상** | 상위 글 11~22개. 짧은 감탄 + 키워드 |
| 사진 묶음 | **연관 쌍만** 2~4쌍 | 같은 공간의 가로/세로, 같은 야경 두 컷 |
| 사진 밀도 | 본문 100~200자당 1장 | 상위 글 76~240 |
| 도입 | 인사 → 공감 → 이 글이 뭘 하나 | 상위 글이 예외 없이 이렇게 연다 |
| 표 | **1개 이하** | 요금처럼 눈으로 스캔하는 것만. 서술은 문단으로 |

### 배치 규칙 — 이게 품질을 가른다

- `afterParagraph` 로 **사진을 그 사진 설명 문장 바로 앞에** 놓는다.
  비우면 개수대로 자동 분배돼 **무관한 문장 사이에 사진이 낀다**
- 순서는 **동선**이다: 역 → 개찰구 → 지상 → 건물 → 접수 → 시설 → 식사 → 나오는 길.
  정보 중요도순이 아니다
- 섹션에 맞는 사진이 없으면 **억지로 넣지 않는다.** 넣어야 한다면 캡션으로 무엇인지 밝힌다

### 내용 규칙

현지인 전용 정보는 **뺀다** (d포인트·PayPay·주민 할인·현지 앱·정기권).
한국 여행자가 결정에 쓰는 것만 남긴다 — 요금·결제 수단, 영업시간·휴관일,
가는 길(역 이름 + 도보 분), 소요 시간, 준비물·타투 규정, 주변 동선, 언어, 예약 필요 여부.
기준: **"이 정보로 내가 뭘 결정할 수 있나"** 를 통과하지 못하면 뺀다.

## 4. 프리뷰로 눈으로 본다

```
node scripts/preview-naver.mjs out/<글>.json           # photoDir 를 자동으로 씀
node scripts/preview-naver.mjs out/<글>.json --photos <폴더>
```

`out/<글>.naver-preview.html` 이 나온다. 발행글 실측값(소제목 30px·본문 16px·줄간격 2.0·
칼럼 886px)으로 그리므로 **여기서 본 것이 곧 결과다.** 모바일은 창을 390px 로 줄여 본다.

확인할 것: `알 수 없는 컴포넌트 0개` · 사진이 설명 문장 바로 앞에 있나 ·
묶음이 연관 쌍인가 · 인용구·캡션 개수가 목표치인가.

## 5. 등록한다

```
node src/cli.js publish out/<글>.json --naver --visibility private
```

- **비공개로 먼저 등록한다.** 인스타 사진이 섞여 있으면 공개는 허가 밖이다.
  공개로 바꾸는 것은 블로그에서 언제든 된다
- 카테고리를 비워 두면 **직전 값이 그대로 쓰인다.** `naver.category` 를 채우거나 `"auto"`
- 사진 업로드 → 본문 주입 순서를 지킨다 (코드가 알아서 한다. 표가 있으면 커서가
  셀 안으로 들어가므로 업로드가 먼저여야 한다)

## 6. 발행 결과를 다시 잰다

```
node scripts/bench-naver.mjs https://blog.naver.com/<id>/<logNo>
```

`imageGroup`·`quotation`·`captionCount`·문단 길이 분포를 확인한다.
**측정값이 목표치와 다르면 기록을 고친다** — 취향이 아니라 수치로 판단한다.

## 함정 (전부 실측으로 데었다)

| 함정 | 결과 |
|---|---|
| 빈 문단으로 여백 만들기 | 발행 시 삭제된다 → **제로폭 공백 문단**을 쓴다 (코드가 처리) |
| 대표 사진을 정사각으로 자르기 | 세로 4:5 컷의 위아래 20%가 날아가 간판이 잘린다 → 로컬 사진은 원본 비율 |
| 자동 1·2·2·1 콜라주 | 관계없는 두 장이 붙어 둘 다 죽는다 → `group` 으로 명시한 쌍만 |
| `placesMap` 해외 검색 | 기본 필터가 `국내` 라 조용히 0개가 된다 → 해외는 쓰지 않고 **주소를 텍스트로** |
| 스톡 사진 | 그 장소가 아닌 사진이 실린다 → `stockPhotos: false` |
| 정규식 선택지 순서 | `image|imageGroup` 순서면 `se-imageGroup` 이 `image` 로 잡혀 **측정이 거짓말을 한다** |

## 아직 없는 것

- `placesMap`(장소 첨부) · `oglink`(예약 링크 카드) — 상위 글 대부분이 쓴다. 다음 작업 1순위
- 대표 사진 브랜드 라벨이 `ISSUE`(연예 글 잔재) — `images.brand`
- 모바일 실측은 아직 창 폭 축소로만 했다 (`m.blog.naver.com` 실측 필요)
