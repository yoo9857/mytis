## 사용자가 정한 사진 기준 (2026-07-28)

> "장소와 아이템, 히트 요소, 여행객들이 실제 블로그에서 얻어갈 수 있는 감성 사진만"

즉 **정보가 되는 감성 사진**만 쓴다. 네 가지로 정리하면:

| 기준 | 뜻 | 예 |
|---|---|---|
| **장소** | 어디인지 알아볼 수 있는 컷 | 입구·간판·전경·객실 |
| **아이템** | 가져갈 정보가 되는 물건 | 어메니티·유카타·음료·티켓·식사 |
| **히트 요소** | 그 장소의 대표 장면 | 노천탕·야경·불감탕처럼 "이거 보러 간다" 는 것 |
| **감성** | 저장하고 싶어지는 톤 | 조명·수증기·야간 조경 |

거르는 것: 사람 얼굴이 주인공인 컷, 장소를 알 수 없는 클로즈업,
분위기만 있고 정보가 없는 사진.

⚠️ 이 기준은 **스톡 사진으로 충족되지 않는다.** 실측에서 스톡은 "아무 사우나",
"두바이 호텔" 을 물어왔다 (photo.js 주석). 장소·아이템·히트 요소는 정의상
**그 장소의 사진**이어야 하므로, 원문 사진과 임베드만이 답이다.
그래서 여행 글은 `images.stockPhotos: false` 로 둔다.
사진이 원저작자 서버에서 렌더링되므로 저작권 문제가 없고, 작성자 계정도 함께 표시된다.

## 수집 도구 — `scripts/ig-photos.mjs`

**글 하나에 쓸 사진은 제목 폴더 하나에 모은다.** 게시물별로 흩어지면 못 고른다.

```
node scripts/ig-photos.mjs --title "스파 라쿠아 야간 1,000엔 할인, 6월부터 상시화" \
  "https://www.instagram.com/p/CmBkjTDp9Fb/?img_index=3" \
  "https://www.instagram.com/p/Cxa8688SHpl/?img_index=3"

node scripts/ig-photos.mjs --title "같은 제목" <주소>   같은 폴더에 이어 담긴다
node scripts/ig-photos.mjs <주소> --dry                 받지 않고 목록만
```

- `out/photos/ig/<제목 슬러그>/<제목 슬러그>-01.jpg …` 로 **번호를 이어 붙인다**
- 어느 게시물의 몇 번째 컷이었는지는 `manifest.json` 의 `shortcode`·`sourceIndex`
  가 기억한다 — 파일명만 보고는 출처를 알 수 없으므로 **크레딧은 manifest 로 되짚는다**
- 같은 제목으로 다시 부르면 **이미 받은 컷은 건너뛰고** 뒤 번호로 이어 담는다
- `--title` 이 없으면 shortcode 폴더로 떨어진다 (한 게시물만 볼 때)

실측에서 걸린 함정 셋 (스크립트 주석에 상세):

- 마크업의 `<img>` 는 **캐러셀 첫 장만** 담는다. 전체 컷은 `contextJSON` 안
  `edge_sidecar_to_children` 에 있다. 이미지 URL 을 정규식으로 긁으면
  **같은 사진의 크기 변형 12개를 컷 12장으로 착각한다**
- `display_resources` 는 **크기순이 아니다.** 1440 → 150 으로 내려가다 1080 정사각
  크롭이 다시 붙는다. `slice(-1)` 을 쓰면 150x150 썸네일을 받는다 → 픽셀 수로 골라야 한다
- `contextJSON` 은 이중 이스케이프된 JSON 문자열이다. `\\"` → `"` 식으로 손으로 풀면
  깨진다. **여는 따옴표부터 닫는 따옴표까지를 따옴표째로 `JSON.parse`** 해야 한다

### 자동화 — 폴더를 주면 네이버폼까지 (2026-07-28 구현)

```
node scripts/preview-naver.mjs out/<글>.json --photos out/photos/ig/<폴더>
node scripts/preview-naver.mjs out/<글>.json          # 아티클의 photoDir 를 씀
node src/cli.js publish out/<글>.json --naver          # 같은 사진으로 발행
```

붙인 자리 셋:

| 파일 | 무엇 |
|---|---|
| `src/photo.js` | `article.photoDir` / `images.localPhotoDir` → **최우선 사진 소스**. 스톡 검색을 건너뛴다. 크레딧은 폴더의 `manifest.json` 에서 `@owner`·permalink 를 되짚는다 |
| `src/images.js` | `source: 'local-photo'` 는 **원본 비율 유지**(간판이 잘리면 장소 증명이 사라진다). 대표 사진도 정사각으로 자르지 않는다 |
| `src/naverDoc.js` | `naver.collage: false` → 사진을 **한 장씩** 세운다 (법칙 ⑨) |

어느 사진이 어느 자리에 갈지는 **아티클이 정한다** — `imageBriefs[].photo` 에 파일 이름,
`afterSection` 에 섹션 번호. 적지 않으면 폴더 순서대로 들어간다.

## 기술 메모

- 인스타 공식 oEmbed 는 토큰 없이 동작한다 (`graph.facebook.com/v20.0/instagram_oembed`).
  존재하지 않는 게시물은 400 + Media Not Found → **존재 확인에 그대로 쓸 수 있다**
- `/embed/` 는 **브라우저 UA 를 보내면 600KB JS 앱 페이지**가 오고, UA 를 빼야
  파싱 가능한 마크업이 온다 (HANDOVER 함정 ⑪). 위 확인에서 302 가 온 것도 이 계열 문제다
- **네이버는 임의 iframe 을 못 받는다.** 티스토리는 iframe 임베드가 되지만 네이버는
  `oglink`(링크 카드)로 바꿔 끼워야 한다 → `oglink` 스키마 실측이 선행 작업이다
- 프리뷰(`out/*.preview.html`)는 로컬 HTML 이라 **iframe 이 그대로 뜬다.**
  발행 전에 임베드가 어떻게 보이는지 프리뷰로 먼저 확인할 수 있다
