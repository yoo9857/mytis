# 오늘 뭐 읽지? — 네이버 책 추천 시리즈

블로그 정체성: 여행 글이 **"어디가지?"** 라면 책 글은 **"오늘 뭐 읽지?"** 다.
**알라딘 월간 베스트(문학 — 소설/시/희곡·에세이)** 에서 중복 없이 한 권을 골라,
**에세이 구조**(공감 도입 → 이어지는 서사)로 쓰고, 블로그 **'문학책' 카테고리**로
발행한다. SEO/GEO 장치(directAnswer·keyTakeaways·서지 표·FAQ)는 에세이 톤과
별개로 유지한다 — 참고 글에서 리듬을 배우되 검색 체계는 우리가 세운다는 원칙.

- 왜 월간인가: 주간은 리커버·굿즈 이벤트로 출렁여 소재가 겹친다.
- 카테고리는 config.json `naver.category: "문학책"` — 블로그에 없으면 발행 때
  경고가 뜨고 직전값이 쓰인다. **블로그 관리에서 카테고리를 먼저 만들 것.**

## 절대 원칙 — 우리는 이 책을 읽지 않았다

여행 글의 "다녀오지 않았으므로 체험을 주장하지 않는다"와 같은 원칙.
감상을 지어내는 순간 글 전체가 거짓이 된다.

- 금지: "가슴이 먹먹해진다", "페이지가 술술 넘어간다", 문장력·반전 평가
- 대신: **누가 그렇게 말했는지 귀속하면 다 쓸 수 있다** —
  "출판사는 ~라고 소개한다" / "○○ 서평은 ~라고 평했다" / "출간 첫 주 1위" (사실)
- 표지 이미지는 쓰지 않는다(저작권). photoQuery 는 독서 분위기 실사로.

## 알고리즘 (2026-07-29 완판 확정 — 두 권 발행으로 검증)

```
① 소재     npm run book
           └ 알라딘 월간 베스트(소설/시/희곡 + 에세이) → SKIP(만화·매거진·수험서)
             → books.done.txt 중복 제외 → 1순위 확정·기록 → 초안 생성까지 자동
② 생성     책 모드(MODE.BOOK) · book.schema.json (스키마가 프롬프트를 이긴다)
           └ 목소리: 제목 해시 → 페르소나 3인 중 1 (정밀한 평론가 / 라디오 북튜버
             / 마감 노동자 소설가) — 같은 책은 항상 같은 목소리
           └ 구조: 프롤로그·목차·줄거리·생각(감상)·기본 정보(서지 표)·결말·포인트
           └ 재미 3요소: 제목 뜻 풀이(검증) · 자기만의 비유 · 위트
           └ 사진 취재: 저자 사진 기사·서점 상품 페이지·무대 기사를 sources 로
             (수확은 코드 — 배너·타권 표지는 필터)
           └ 기계 검사: 조사 · 어미 3연타 · "흐름" 경고
③ 검토     사람이 한다 (publish-review-loop) — 여기서 손대는 것:
           · 읽은 척 문장(감상 창작) = 전량 재작성 대상
           · 소제목의 책 제목 반복 · 페르소나 시그니처 누락
           · callout = 검증된 책 속 문장만 (예스24 '책 속으로' 등에서 확인해 주입.
             '책 속으로'가 안 긁히면 **뒤표지·표지 실물 이미지**에서 문장을 읽어 검증)
           · 사진 큐레이션: 남길 것 = 한국판 표지·저자·펼침 미리보기·무대/분위기,
             버릴 것 = 타권·원서 표지 스캔·배너 → out/photos/book/<제목>/ 에 고정
           · ⚠️ **스탯 카드(그라디언트 문구 카드) 금지** — 책 에세이 톤과 안 맞는다
             (2026-07-29 독자 피드백: "배경이나 관련 이미지가 아니니 보기 좋지 않음").
             사진 못 채우는 브리프는 **삭제**한다. 수치는 본문 bullets 가 이미 말한다.
           · **작가+글귀 카드는 폼 필수** — 빠뜨리면 독자가 알아챈다 (같은 날 피드백).
             저자 무료 사진이 없으면 sources 보도사진에서 크롭(감수는 발행자).
             글귀 카드 팔레트는 **표지 지배색을 따른다** — cv2.kmeans 로 뽑아
             `--palette "#bg1,#bg2,#ink,#sub,#accent"` 로 넘긴다 (크림 기본값은
             표지가 어두운 책에서 남의 옷이다)
           · **기사성 대목(순위·방송·후원)에는 관련 실물 사진** — 출판사 소개 이미지의
             장면 부분 크롭, 기사 사진 등. 관련 없는 스톡·빈 카드로 채우지 않는다
           · photoDir + imageBriefs[].photo/group/afterSection/noText 로 배치
             (대표=글귀 카드 또는 장면 + noText:true, 카드 콜라주=생각 뒤,
              표지=기본 정보 뒤 · noText 없이 비우면 글 제목이 자동으로 얹힌다)
④ 프리뷰   node scripts/preview-naver.mjs "out/<글>.json" --photos <photoDir>
⑤ 발행     npm run publish -- "out/<글>.json" --naver
           └ 발행 직전 lint 재검사(손 편집 안전망) → 글감 책 카드(대표 아래·가운데)
             → 카테고리 "오늘 뭐 읽지?" → 발행 → books.done.txt 에 URL 기록
             → 다음 글이 "지난 오늘 뭐 읽지?" 로 자동 연결 (시리즈 다리)
```

## 책 모드가 다른 모드와 다른 점 (src/mode.js MODE.BOOK)

| 단계 | 책 모드 | 왜 |
|---|---|---|
| 원문 사진 | ✕ | 원문 기사가 없다 |
| 관련 기사 사진 | ✕ | 서평 기사 사진은 표지 스캔이라 더 위험하다 |
| 유튜브 임베드 | ✕ | 북트레일러는 공식 채널 판별이 어렵다 (v1) |
| SNS 임베드 | ✕ | 저자 SNS 근황은 책 소개와 무관하다 |
| 표 | **○** | 서지 정보가 표의 정석 — 네이버 실표로 나간다 |

## 글의 뼈대 (buildBookPrompt 가 시킨다)

한 줄 정리(왜 오늘 이 책인가) → 어떤 책인가(스포일러 없이, 귀속) →
왜 지금인가(순위·화제) → 저자는 누구인가 → **서지 정보 표** →
어떤 독자에게 맞나("전작 ○○를 좋아했다면" — 만능 추천 금지) → FAQ

## 사진 — 서치가 기본, 세 겹으로 만든다

**생성 단계가 사진을 직접 서치한다** (2026-07-29 확립): buildBookPrompt 의
"사진 취재" 지시가 저자 사진 실린 기사·서점 상품 페이지·무대 관련 기사를
sources 에 넣게 하고, 수확기(관련 기사 사진)가 그 페이지들의 사진을 걷는다.
codex 에게 사진 URL 을 직접 받지 않는다 — URL 은 지어내지만 페이지는 못 지어낸다.

| 자리 | 소스 | 근거 |
|---|---|---|
| 실제 표지 (카드) | **글감 책 카드** (발행 때 자동 첨부) | 네이버 공식 썸네일이라 합법 |
| 표지 실물컷·저자 사진·무대 장면 | sources 페이지에서 수확 (서점 상품컷·보도사진) | 보도사진 위험은 발행자 감수 — 연예 글과 같은 기준 |
| 연출컷 (펼친 페이지·포스터·독서 일지) | `scripts/book-shots.mjs` (OpenAI 생성) | 표지·본문을 재현하지 않고 분위기만. 글자를 그리게 하지 않는다 |
| 저자 실물 (자유 라이선스) | entities nameEn → 위키미디어 | 있을 때만 |

**발행 전 눈으로 거르는 기준** (투명한 나선 실측 — 수확 12장 중 8장이
일본 문고판 타권 표지였다):
- 남길 것: 한국판 표지 실물컷 1 · 저자 사진 1 · 무대/현장 장면 1~2
- 버릴 것: 타권·원서 표지 스캔, 로고, 배너
- 대표(슬롯 0)는 장면 사진이 낫다 — 표지 위에 헤드라인 글자가 얹히면 글자끼리 싸운다

`book-shots.mjs` 는 `OPENAI_API_KEY` 가 필요하다. 결과는
`out/photos/book/<제목>/` 에 쌓이고, 아티클의 `photoDir` + `imageBriefs[].photo`
로 지정해 쓴다 (여행 글의 눈으로 고른 사진과 같은 경로).

## 독자 피드백으로 굳은 기준 (2026-07-30 · 안녕, 피터팬 두 번 발행하며)

1. **담백하게.** 매 문단을 의미 부여로 닫으면("이 순위는 판매 숫자만 말하지 않는다")
   전부 힘준 문장이 되어 아무것도 남지 않는다. 의미 부여는 글 전체에 두세 번.
   사실이나 장면으로 끝나는 섹션이 절반은 되어야 한다. (buildBookPrompt 에 반영됨)
2. **시각 자료를 아끼지 않는다.** 실물 사진 목표 6~8장 — 표지·뒤표지·펼침·저자·
   행사/방송 장면. 글이 말하는 사건(순위 진입·방송·후원)마다 보여줄 그림이 있어야
   한다. 스탯 카드로 때우지 않는다.
3. **글귀 카드는 표지 색을 입는다.** `--palette` 로 표지 지배색(cv2.kmeans)을 넘긴다.
4. **발행 후 수정은 불가능하다** (편집 진입 URL 전부 막힘 — HANDOVER 실측).
   새로 발행 + 옛 글 삭제 + books.done.txt 갱신뿐이다. 그러니 **발행 전에 다 잡는다.**

## 참고 글에서 배운 것 (bigsky04/224319619438 · 어린 왕자 — 2026-07-29 실측)

- **관점 하나로 꿴다**: 제목부터 "나이마다 다르게 읽히는" 이라는 각도 하나,
  본문도 그 각도(나이대별 독법 → 결말의 두 독법)로만 간다. 서지 나열이 없다.
- **책 속 문장이 뼈대**: 유명 구절을 인용구로 세우고 그 아래 해설을 붙인다.
  → 우리 구현: sections[].callout 에 **공개된** 책 속 문장, 책 모드에서
  기본 인용구(큰따옴표)로 렌더링.
- 소제목 0개·긴 문단(p75 105자)은 따라가지 않는다 — GEO(소제목)와
  가독성 폼(mobileLines)은 우리 체계를 유지한다.

## 실측 기록

- 2026-07-29: 알라딘이 예스24보다 수험서 노이즈가 적다
  (예스24 상위 5권에 수험서 2권, 알라딘 0권). 만화·매거진은 제목·출판사로 거른다.
- 월간 베스트 URL: `wbest.aspx?BestType=MonthlyBest&BranchType=1&CID=<분야>&Year=&Month=`
  — CID 1 = 소설/시/희곡, 55889 = 에세이. 두 분야를 순위 순으로 섞는다.
- 소재가 떨어지면 알라딘 신간 페이지나 다른 문학 분야로 넓힐 수 있다 — 그때
  book-today.mjs 에 URL 만 바꾸지 말고 SKIP 규칙이 그 분야에 맞는지부터 볼 것.
