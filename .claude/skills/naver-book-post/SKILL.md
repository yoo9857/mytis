# 오늘 뭐 읽지? — 네이버 책 추천 시리즈

블로그 정체성: 여행 글이 **"어디가지?"** 라면 책 글은 **"오늘 뭐 읽지?"** 다.
**알라딘 월간 베스트(문학 — 소설/시/희곡·에세이)** 에서 중복 없이 한 권을 골라,
**에세이 구조**(공감 도입 → 이어지는 서사)로 쓰고, 블로그 **'문학책' 카테고리**로
발행한다. SEO/GEO 장치(directAnswer·keyTakeaways·서지 표·FAQ)는 에세이 톤과
별개로 유지한다 — 참고 글에서 리듬을 배우되 검색 체계는 우리가 세운다는 원칙.

- 왜 월간인가: 주간은 리커버·굿즈 이벤트로 출렁여 소재가 겹친다.
- 카테고리는 config.json `naver.category: "문학책"` — 블로그에 없으면 발행 때
  경고가 뜨고 직전값이 쓰인다. **블로그 관리에서 카테고리를 먼저 만들 것.**

## 절대 원칙 — 우리는 이 책을 읽지 않았다

여행 글의 "다녀오지 않았으므로 체험을 주장하지 않는다"와 같은 원칙.
감상을 지어내는 순간 글 전체가 거짓이 된다.

- 금지: "가슴이 먹먹해진다", "페이지가 술술 넘어간다", 문장력·반전 평가
- 대신: **누가 그렇게 말했는지 귀속하면 다 쓸 수 있다** —
  "출판사는 ~라고 소개한다" / "○○ 서평은 ~라고 평했다" / "출간 첫 주 1위" (사실)
- 표지 이미지는 쓰지 않는다(저작권). photoQuery 는 독서 분위기 실사로.

## 순서 (한 권을 처음부터 끝까지)

```powershell
# 1. 오늘의 책 고르기 — 알라딘 주간 베스트에서, 쓴 책은 books.done.txt 로 제외
node scripts/book-today.mjs              # 후보 훑어보기
node scripts/book-today.mjs --pick --save  # 1순위 확정 + 기록

# 2. 초안 생성 — "책:" 접두사가 책 모드(MODE.BOOK)를 연다
npm run draft -- "책: <제목> — <저자> (<출판사>)" --verbose

# 3. 검토 — 발행 전에 반드시 독자처럼 읽는다 (publish-review-loop)
#    · 읽은 척 문장이 없는가 (감상 창작 = 전량 재작성 대상)
#    · 서지 표가 있는가 (제목·저자·출판사·출간일·쪽수)
#    · 인용에 출처가 붙었는가 · "흐름" 같은 AI 단어가 없는가
#    · 조사 경고(lintKo)가 떴으면 눈으로 확인

# 4. 네이버 프리뷰로 폼 확인 (SSS 폼 — naverDoc.js 가 원본)
node scripts/preview-naver.mjs "out/<글>.json" <이미지들>

# 5. 발행
npm run publish -- "out/<글>.json" --naver
```

## 책 모드가 다른 모드와 다른 점 (src/mode.js MODE.BOOK)

| 단계 | 책 모드 | 왜 |
|---|---|---|
| 원문 사진 | ✕ | 원문 기사가 없다 |
| 관련 기사 사진 | ✕ | 서평 기사 사진은 표지 스캔이라 더 위험하다 |
| 유튜브 임베드 | ✕ | 북트레일러는 공식 채널 판별이 어렵다 (v1) |
| SNS 임베드 | ✕ | 저자 SNS 근황은 책 소개와 무관하다 |
| 표 | **○** | 서지 정보가 표의 정석 — 네이버 실표로 나간다 |

## 글의 뼈대 (buildBookPrompt 가 시킨다)

한 줄 정리(왜 오늘 이 책인가) → 어떤 책인가(스포일러 없이, 귀속) →
왜 지금인가(순위·화제) → 저자는 누구인가 → **서지 정보 표** →
어떤 독자에게 맞나("전작 ○○를 좋아했다면" — 만능 추천 금지) → FAQ

## 사진 — 세 겹으로 만든다

| 자리 | 소스 | 근거 |
|---|---|---|
| 실제 표지 | **글감 책 카드** (발행 때 자동 첨부) | 네이버 공식 썸네일이라 합법 |
| 연출컷 (실물 느낌 책·펼친 페이지·포스터·독서 일지) | `scripts/book-shots.mjs` (OpenAI 생성) | 표지·본문을 재현하지 않고 분위기만. 글자를 그리게 하지 않는다 — 문구는 카드 렌더러가 얹는다 |
| 저자 실물 | entities nameEn → 위키미디어 | 있을 때만. 히가시노 게이고처럼 공개 사진이 없는 작가는 억지로 찾지 않는다 |

`book-shots.mjs` 는 `OPENAI_API_KEY` 가 필요하다. 결과는
`out/photos/book/<제목>/` 에 쌓이고, 아티클의 `photoDir` + `imageBriefs[].photo`
로 지정해 쓴다 (여행 글의 눈으로 고른 사진과 같은 경로).

## 참고 글에서 배운 것 (bigsky04/224319619438 · 어린 왕자 — 2026-07-29 실측)

- **관점 하나로 꿴다**: 제목부터 "나이마다 다르게 읽히는" 이라는 각도 하나,
  본문도 그 각도(나이대별 독법 → 결말의 두 독법)로만 간다. 서지 나열이 없다.
- **책 속 문장이 뼈대**: 유명 구절을 인용구로 세우고 그 아래 해설을 붙인다.
  → 우리 구현: sections[].callout 에 **공개된** 책 속 문장, 책 모드에서
  기본 인용구(큰따옴표)로 렌더링.
- 소제목 0개·긴 문단(p75 105자)은 따라가지 않는다 — GEO(소제목)와
  가독성 폼(mobileLines)은 우리 체계를 유지한다.

## 실측 기록

- 2026-07-29: 알라딘이 예스24보다 수험서 노이즈가 적다
  (예스24 상위 5권에 수험서 2권, 알라딘 0권). 만화·매거진은 제목·출판사로 거른다.
- 월간 베스트 URL: `wbest.aspx?BestType=MonthlyBest&BranchType=1&CID=<분야>&Year=&Month=`
  — CID 1 = 소설/시/희곡, 55889 = 에세이. 두 분야를 순위 순으로 섞는다.
- 소재가 떨어지면 알라딘 신간 페이지나 다른 문학 분야로 넓힐 수 있다 — 그때
  book-today.mjs 에 URL 만 바꾸지 말고 SKIP 규칙이 그 분야에 맞는지부터 볼 것.
